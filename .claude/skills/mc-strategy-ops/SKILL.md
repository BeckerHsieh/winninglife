# MultiCharts 策略操作規範（mc-strategy-ops）

這台電腦是**實盤帳戶**（MXF1、IRF1、股期都有真實部位），任何操作先求不出事，再求效率。

## 一、鐵則

1. **不開自動交易、不下單、不取消委託。**
   - 使用者明確要求時，才可以「關閉」指定那一張圖的自動交易。
   - 過程中跳出平倉或部位確認視窗，一律選取消/否，並回報視窗原文。
2. **新策略一律用 `0_NO6_` 開頭**，`mc/*.pla` 檔名和 MC 內的訊號名稱都一樣，例如 `0_NO6_MV_Cross_BB2`。
   - 不改名、不覆寫舊的原版訊號（0_NO3 / 0_NO5 系列）。
   - 命名前先檢查 `mc/` 和 `C:\ProgramData\TS Support\Concord MultiCharts64\StudyServer\Studies\SrcEl\Strategies\` 有沒有同名。
3. **`mc/` 下既有語法檔修改前先備份**：`*.pla.bak_YYYYMMDD[_HHMM]`，不可覆寫既有備份。
4. **改圖表訊號前先備份工作底稿**：`MC_wsp\<name>.wsp.bak_YYYYMMDD`。
   - 被取代的訊號只「取消勾選」，不要移除。
   - 動手前先讀一次目前的訊號清單和狀態並回報，可能有人改過。2026-11-07 MC 重開後就發現狀態被改過。
5. **工作底稿只有在使用者要求時才存檔**，而且要先確認 MC 回測數字和預期一致。
   - 存檔前另外備份一份 `_presave`。
   - 存完要確認修改時間有更新，並搜尋檔案內容確認引用的是新訊號名稱。
   - 沒存檔就重開 MC，修改會消失。
6. **repo 的 `.pla` 改了不會自動生效**，必須在 PowerLanguage Editor 匯入並編譯。查問題時要考慮 MC 正在跑的可能是舊版程式。
7. **回測前先確認圖表資料範圍**（設定物件 → 商品分頁的起訖日）和預期一致。2026-11-07 曾發生已存檔是 2021/1/1 起，事後被改成 2025/1/1 起，導致回測只剩 200 筆。比對 MC 和本機結果時，本機要切成同樣的資料起點，因為 MaxBarsBack 暖機和 `loseCnt` 都會受影響。
8. GUI 操作一律交給 `re-agent`，prompt 裡寫明上面的限制。
   - 結束時還原視窗大小和分頁，回報所有檔案的完整路徑。
   - 讀不到的資料要直接說讀不到，不要推測。

## 三、股期下單常見問題（CYF / IRF / OWF）

查「有訊號沒成交」時，先照這幾點檢查：
- **漲跌停**：委託價超過漲跌停會被退單（「超過該商品漲跌停價」）。漲跌停是前一日結算價 ±10%，程式用前一日收盤 ±9% 估算。
- **tick 單位**：不是 tick 整數倍的價格也會被退單。股期 tick：未滿 10 元 0.01、10～50 元 0.05、50～100 元 0.1、100～500 元 0.5、500～1000 元 1、1000 元以上 5。
- **收盤那根（13:45）送出的單**：實際掛在隔天第一根，要用隔天的漲跌停檢查。收盤後不送市價單，出場訊號延到隔天。
- **市價單沒成交**：TAIFEX 市價單是 IOC，冷門股期常被取消、成交 0 口。MC 非同步模式下，策略仍認為 MP=1、券商卻是空手，結果進場單被擋（不加碼），出場單一直被拒，直到自動交易自動關閉。
- **手動下單**：在策略跑的商品上手動下單會造成部位不同步。重新開啟自動交易時，部位輸入視窗要填券商實際部位。建議勾選「當經紀商回報委託拒絕」重新計算，或改用同步模式。
- **流程**：先請 `re-agent` 讀委託與部位追蹤器，拿到退單原文後再改程式。

## 四、本機回測與優化

工具在本技能的 `scripts/`：
- `mc-bt-engine.js`：重現 MXF-18 掛的 5 個訊號，以及 `0_NO6_MV_Cross_BB2`（設定 `deploy:true`）。用法：`run(bars, cfg)`、`stats(trades, from, to)`、`loadBars(csv)`。
- `mc-bt-compare.js <bars.csv> <mcTrades.csv> [config.json]`：和 MC 交易清單逐筆比對。時間或價格有差異時 exit code 為 2。
- `mxf18-bb2.config.json`：目前 MXF-18 部署的設定。

### MC 回測規則（已驗證能逐筆重現，新引擎要照這些做）
- 前 MaxBarsBack 根 K 棒不交易（MXF-18 是 2000 根）。
- 收盤產生的單在下一根成交：市價單用開盤價；停損單用 max/min(開盤價, 停損價)。
- `MaxPositionProfit`：用最高/最低價計算的浮盈，**扣單邊手續費**（200 元 = MXF 4 點）。`PositionProfit(k)`：**扣雙邊手續費**（400 元）。
- 同一根可以先出場再進場：持倉中產生的同方向進場單，只要同一根有出場單就會成交（先處理出場）。
- 內建 Stop Loss 和訊號停損單在同一根 K 棒競爭，價格先碰到的成交；跳空開盤時兩張都在開盤價成交，MC 標成訊號停損單的名稱。
- `Highest/Lowest(price, 0)` 回傳 price 本身，條件成立。
- MXF：每點 50 元，手續費 Fixed-200（每口每邊）。

### 優化流程（避免過度擬合）
1. **先診斷再調參**。例如 MXF-18 近兩週沒動作，原因是只做多遇上 −20% 急跌，加上 `loseCnt` 鎖死。
2. **資料**：請 `re-agent` 匯出圖表 K 線和交易清單，再用 `mc-bt-compare.js` 確認**本機和 MC 時間、價格 0 差異**，才開始優化。
3. **切期間**：訓練期 2021-02～2024、驗證期 2025～最新。參數只用訓練期挑，要求訓練期每年都賺，參數前後微調仍然賺；挑完才看驗證期一次。
4. **報告內容**：滑價每邊 1～3 點的影響、逐年和原策略比較、最大回落增加多少（老實寫）。
5. **保持相容**：新參數設成預設值時，結果必須和原策略完全相同（逐筆證明），新行為放在 input 後面開啟。
6. **部署**：`re-agent` 匯入編譯 → 套到圖表回測 → 和本機逐筆比對 → 使用者要求才存檔。
